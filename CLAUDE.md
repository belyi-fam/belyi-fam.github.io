## Commands

Package manager: **Yarn** (yarn.lock is committed; `package-lock.json` is gitignored). Node version pinned to 22 in `.nvmrc`.

- `yarn dev` — start Next.js dev server on http://localhost:3000
- `yarn build` — production build
- `yarn start` — run the built app
- `yarn lint` — `next lint` (extends `next/core-web-vitals`; `react/no-unescaped-entities` is disabled)

There is no test suite configured.

## Architecture

### Next.js Pages Router with a custom `src/app/` layout

The repo uses the **Pages Router** (`pages/`), not the App Router — despite the `src/app/` directory. `src/app/` is just the project's home for shared UI; it is **not** the Next.js `app/` directory. The unused `src/app/layout.tsx` is a leftover and is not the active root layout — `pages/_app.tsx` is.

- `pages/index.tsx` → renders `src/app/pages/MainPage` (the family interactive page)
- `pages/aoc.tsx` → standalone Advent of Code countdown
- `pages/cleo.tsx` → standalone cat profile page
- `pages/api/bio.ts` → POST endpoint backing the bio lookup
- `pages/_app.tsx` is the real root; it imports global Tailwind (`globals.css`) and SCSS (`styles/index.scss`)

Path alias: `@/*` → `src/*` (see `tsconfig.json`).

### Family-member combinatorics (the central abstraction)

`src/common/types.ts` defines six `Member` enum values (Igor, Kass, Katya, Leo, Syd, Tanya) and exports a constant for every possible alphabetically-sorted concatenation of human members (e.g., `IGORKASS`, `IGORKASSKATYA`, …, `IGORKASSKATYALEOTANYA`). These strings are used as **dictionary keys** throughout `src/data/bio.ts` for archetype names, descriptions, and image lists.

Critical helper: `getMembersString(members)` in `src/common/types.ts`
- Filters out **Syd** unless he's the only selected member (Syd has his own dedicated bio and is not part of the human-combination matrix).
- An empty selection or 5+ humans collapses to `IGORKASSKATYALEOTANYA` (the whole-family key).
- Otherwise sorts the remaining members alphabetically and concatenates.

**When adding new content to `src/data/bio.ts`:** new entries must be keyed by the constant (e.g., `[KASSLEOTANYA]`) — not by a hand-typed string — so the alphabetical sort matches what `getMembersString` produces. Several keys (`KASSLEOTANYA`, `KATYALEOTANYA`, `IGORKASSKATYALEO`, `KASSKATYALEOTANYA`) are intentionally `[]` placeholders marked `TODO`; `getBioImages` falls back by progressively expanding the group to find images.

### Selection state lives in the URL

`src/app/hooks/useMembersSelected.tsx` is the single source of truth for which family members are selected. It reads/writes the `selected` query param as a comma-separated list and uses `router.push(..., { shallow: true })` so changes don't refetch the page.

Consequence: the hook depends on `useRouter` from `next/router` (Pages Router). Any component that uses it must be `'use client'` and must run inside the Pages Router tree.

### Bio fetch flow

1. `BioPage` calls `fetchBio(membersSelected)` (in `src/app/api/bio.ts`) on selection change.
2. That POSTs to `/api/bio` (`pages/api/bio.ts`).
3. The handler calls `getBio(members)` from `src/data/bio.ts`, which:
   - looks up the archetype name and description by `getMembersString(members)`,
   - calls `getBioImages(members)` which expands the group when no images exist for the exact combination,
   - returns `{ name, description, images }`.

The `useEffect` in `BioPage` keys off `getMembersString(...)` (not the array reference) so reordering selections doesn't refetch.

### Styling

- **Tailwind** for layout/utility classes (`tailwind.config.ts` scans `pages/**` and `src/**`).
- **SCSS** for animations and the per-member blur background (`src/app/styles/background.scss`).
- `src/app/output.css` is a checked-in compiled Tailwind file imported by the standalone pages (`aoc.tsx`, `cleo.tsx`) — it's a workaround for those pages, not generated by the build.
- `BlurBackground` composes per-member CSS classes (`{member-lowercase}-background`) so adding a new member requires matching SCSS rules.

### Images

`next.config.js` whitelists `localhost:3000` and `belyi.co` for `next/image`. All current images are local under `public/img/` and `public/img/cleo/`. `public/.nojekyll` is present, suggesting GitHub Pages was a prior deploy target — but the API route (`pages/api/bio.ts`) requires a Node runtime, so static export is not viable as written.
